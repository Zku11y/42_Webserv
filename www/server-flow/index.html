Startup & dispatch

Each poll entry represents one FD. The listener list and pipe map tell the loop how to handle it.

server.cpp · 384, 802
main() loads the requested config

Ignore SIGPIPE, construct Config, and enter connection_handler(). A missing config argument or a config exception exits with status 1.

add_listener() for each configured endpoint

Create, bind, and listen on the nonblocking socket. Successful listeners go in serverfds and pollfds with POLLIN.

Call poll(), then scan pollfds backward

The wait is 100 ms. With zero ready events the pass still checks timeouts, buffered requests, and child exit. EINTR retries poll. A fatal poll error or an empty vector exits the loop.

CGI flow

CGI handoff & completion

The parent owns the pipe FDs. The child PID is checked separately after the FD scan.

server.cpp · 265–365, 674–759
Execution starts the CGI child

The child connects the pipes to its stdin and stdout and calls execve(). The server gets the PID, the stdin write FD, and the stdout read FD in client.cgi_rsp.

WAIT and sk_add_pipes()

Set socket events = 0, start the five-second CGI timer, and register nonblocking parent pipe FDs. With an empty body, close stdin immediately so the child sees EOF. If registration fails, queue client cleanup.

On later poll passes, dispatch each ready pipe

CgiPipeMap::find(fd) gives sk_handle_pipes() the owner and the pipe direction. A failed handler or output above 20 MiB records the owner’s socket FD in cgi_pipe_errors.

stdin · POLLOUT
Send request-body bytes

body_offset advances by the actual write() count. After the last byte, or when the script closes its input, close and unregister the pipe and set stdin_write_fd = -1.

stdout · POLLIN / POLLHUP
Collect CGI output

Append each read to raw_output. On hangup there may still be bytes to read. Zero marks stdout_eof, closes the pipe, and sets stdout_read_fd = -1.

After the FD scan
Inspect clients still in WAIT

Pending disconnect cleanup takes priority. Otherwise check pipe failure or timeout first, then call waitpid(pid, &status, WNOHANG) if the child is still unreaped.

Still pending
Return to poll()

Child exit and stdout EOF can arrive in either order. A zero waitpid() result or pending stdout keeps the client in WAIT.

EOF + child reaped
ft_cgi_finish(client)

Close any remaining pipe and pass output and exit status to the finalizer. It fills rsp with a response or a 502. Build it, switch to WRITE, and arm socket POLLOUT.

Response flow
Pipe failure / deadline
Use the CGI error path

Close both pipes and retire the child if needed. Find the socket’s index again, then build 502 or 504 with WRITE_THEN_CLOSE.

Cleanup flow

Two completion checks. stdout_eof says all output bytes are collected. child_reaped says the exit status has been collected. child_exit_status tells the finalizer how the process ended.

What actually happens when waitpid() fails?

EINTR leaves the client in WAIT for a retry. ECHILD clears the PID before queuing disconnect cleanup. Other errors also queue socket cleanup in this snapshot.

Send the response

Socket POLLOUT drives the send. A file response has a serialized prefix and a separate body FD.

server.cpp · 586–668
Send from rsp.responc at tw_bytes

For inline replies this includes the body. For file-backed replies it contains the headers. Advance by the actual send() count and refresh the idle timer on progress.

Have the serialized bytes finished?

Keep the current offset for the next writable pass if there are bytes left. A negative send() queues cleanup.

Inline response
Check response completion

With body_fd == -1 and an empty response_buffer, all bytes are sent.

File-backed response
Read and drain bounded chunks

When response_buffer is empty, read up to fd_bytes_left bytes, bounded by the chunk size. Decrease the count on read(), and trim the buffer on send(). An early EOF or read error queues cleanup.

All bytes sent
Finish once all response bytes are sent

For a file reply, close its FD when the count and buffer are empty. Completion needs all serialized bytes sent, no open file, and no pending chunk.

WRITE
Keep the connection

Reset the parser and send state, preserve request_buffer, switch to READ, and arm POLLIN.

Close & reap

Keep the owning Client alive until its pipe entries are gone. Keep the PID until the child is reaped.

server.cpp · 414, 674–795
clients_to_close
Remove the connection

Unregister and close both pipes, close any response file, stop any unreaped CGI child, then remove the socket and erase the client.

cgi_pipe_errors / CGI deadline
Keep the socket for the error reply

The WAIT sweep closes both pipes and stops any unreaped child. The socket remains registered so it can send the error before closing.

If the child still needs reaping
Store the PID in retired_pids

The final sweep calls waitpid(pid, NULL, WNOHANG). A positive matching result or ECHILD removes the PID. A child still awaiting reaping stays in the list for another pass.

Timers. The ordinary socket idle timer is 500 ms and excludes WAIT. The CGI deadline is five seconds from entry to WAIT.

Which variable owns what?

Keep these names handy while reading the loop.

server.hpp · 33–114
Containers and lifetime
pollfds
Readiness registrations for listener, socket, and pipe FDs. events is what you request. revents is what poll reports for this pass.
serverfds / clients / pipes
Listener metadata, clients keyed by socket FD, and CGI entries keyed by pipe FD. A pipe entry’s p_type selects stdin or stdout. Its Client& borrows the owner from clients.
clients_to_close / cgi_pipe_errors
Client socket FDs queued during this poll pass. The first removes the connection. The second lets a live socket receive a CGI error reply.
retired_pids
Child PIDs that still need a reap after CGI failure or client cleanup. This list survives across poll iterations.
One CgiState per client
stdin_write_fd / stdout_read_fd
The parent ends used to send body bytes and collect output, respectively. Closing either end sets its field to -1.
body_offset / raw_output
Bytes already written from the request body, and bytes collected from the script so far.
stdout_eof / child_reaped
Two independent facts tracked across poll passes. The first comes from a zero-byte stdout read, the second from waitpid().
pid / child_exit_status
The process identifier and the saved wait status. Interpret the status after child_reaped is true.
Request and response bytes
request_buffer / parsed_req
Incoming bytes waiting for the parser, and the complete request handed to execution. The parser consumes data from the front of the buffer.
rsp.responc / tw_bytes
Serialized bytes for the socket, and the number already sent from that string.
rsp.body_fd / fd_bytes_left
Optional response file and the number of advertised bytes still to read from it.
response_buffer
A file chunk already read from disk whose remaining bytes still need to go to the socket.
r_bytes / tr_bytes / w_bytes
The last recorded socket read, total received bytes, and last recorded serialized-response write. The send position is tracked separately in tw_bytes.
t_out
The timestamp used for ordinary I/O progress or for the start of the CGI deadline while the client waits.
