01

File response length

Send exactly the number of bytes advertised in Content-Length.

Problem

The current sender reads the open file until EOF. If the file grows, the next bytes on the connection can exceed the advertised length. If it shrinks, the server can return to READ with part of the response still owed. Your negative-read branch already queues cleanup.

Solution

Give the poll loop sole ownership of file reads. Remove the small-file FD read in HttpResponseBuilder::build(), so responc contains headers only whenever body_fd is open. Set a new size_t file_bytes_left field to rsp.body_size after building a file response. Start and reset it at zero.

A partial send() leaves bytes in response_buffer for the next writable pass. An empty file closes immediately. If read() fails or returns zero while bytes are owed, the cleanup pass closes both descriptors. The status and headers are already on the wire.

Check the fix

Compare the bytes received for an empty file, a small file, and a multichunk file. A file that grows should send no extra bytes. An early file EOF should close the connection.

02

CGI failures and timeouts

Keep the socket available long enough to send the CGI error.

Problem

A WAIT timeout, a failed pipe, or a failed pipe registration currently queues the entire client for closing. The configured 504 and 502 responses can therefore go unsent.

Solution

During the indexed poll scan, record a pending CGI error by client socket FD. Use 504 for a CGI deadline, 502 for output and pipe failures, and 500 for local setup errors. Keep transport failures in clients_to_close. Apply CGI errors after the indexed scan, when removing both pipes can safely shift the vector.

In the normal CGI finalization loop, skip FDs present in either queue. Keep the EINTR retry and invalidate the PID on ECHILD before queuing a 500 for a failed waitpid(). Reuse sk_retire_cgi() when the socket itself disappears. The retired-PID sweep calls waitpid(..., WNOHANG) after either path.

Check the fix

Let a development CGI exceed the deadline and confirm the client receives 504. While it runs, make a separate static request. After timeout or disconnect, verify the child is reaped and both pipe registrations disappear.

03

Connection close and keep-alive

Apply the request’s close decision to both successful response paths.

Problem

Ordinary and CGI responses currently choose WRITE even when the request asks for Connection: close. The response sends, then the client returns to READ until it disconnects or times out.

Solution

Match the exact comma-separated close token, ignoring case and surrounding spaces. Before serializing, add the response header and select WRITE_THEN_CLOSE. Use one helper for the static path and for CGI after ft_cgi_finish(). The parsed request is still available when CGI finishes.

Replace the existing serialization and write-state setup with this helper in both paths. If you also implement the file-length lesson, set client.file_bytes_left to client.rsp.body_size after build() when body_fd is open, and to zero otherwise. The static path already has the socket poll entry. In CGI finalization, call the helper where you find that entry by FD. Keep parser errors on the existing forced-close helper, and keep buffered-request parsing outside the POLLIN check after returning to READ.

Check the fix

Send a normal request with Connection: Close and look for the close response header and prompt EOF. Repeat with CGI, then verify two ordinary requests can still share one connection.

04

Initialize client state

Give each new connection well-defined counters, state, and ownership.

Problem

add_client() fills many fields before inserting into the map, but other scalar members are still copied uninitialized. The parser also owns a separate HttpRequest whose localPort needs initialization. This is an initialization defect. The prior smoke checks did not show a segfault.

Solution

Initialize defaults where the objects are constructed. Keep -1 as the unused descriptor value and keep the constructor list in declaration order. add_client() then sets the accepted socket, addresses, timestamp, and parser body limit.

Check the fix

Build with the existing warning flags. Check that a newly constructed client starts in READ, owns no file response or CGI pipe FD, and has zeroed byte counters.

05

Listener setup and fatal errors

Use the IP already parsed by config and propagate startup failures.

Problem

add_listener() stores a parsed uint32_t IPv4 value in a signed int. A valid address with its high bit set can hit the negative check. The loop ignores listener setup failures, and main() discards the loop’s return value.

Solution

Bind using ServerConfig::getIp(). Continue storing getHost() in the listener’s routing metadata. A simple startup policy is to require every configured listener to bind, close any that already opened when one fails, and return a nonzero status.

Remove the duplicate convert_ip(std::string &) if it has no callers. Ask the config owner to compare duplicate endpoints using getIp() and the port. For a fatal poll() error after startup, close remaining clients and retire their CGI children before returning failure. Once the last listener is lost, stop accepting work and clean up for exit.

Check the fix

Start with a free configured port, then with that port already occupied. The second startup should report the bind error and return nonzero. Check that ordinary localhost routing still works with the padded IP spelling in default.conf.

06

Request deadlines and backpressure

Limit request time independently of gaps between reads.

Problem

t_out is refreshed by each successful receive. An incomplete request can stay alive as long as bytes keep arriving within the idle window. A listener under descriptor pressure can keep waking poll() when accept() cannot make progress. Synchronous body logging also occupies the event loop.

Solution

Give each request a separate start timestamp. Start it when the first bytes are available, including bytes left over after the previous response. Keep your existing idle timer, and choose a separate overall limit. On descriptor exhaustion, pause the affected listener briefly and keep servicing existing clients. Log request metadata and byte counts.

Have add_client() report descriptor exhaustion by checking EMFILE and ENFILE immediately after a failed accept(). In listener dispatch use the current pollfds[i] after a failure. A successful accept may append to the vector, so acquire a fresh index before accessing it again. Before the next poll(), find each paused listener by server.fd to rearm it.

Check the request deadline on passes without socket readiness as well. The 10-second example applies to receiving and parsing. CGI and sending have separate timers. If your subject permits a monotonic time source, use it so clock corrections cannot move a deadline. When handling allocation failures, roll back the map insertion and close the new FD if its poll entry could not be added.

Check the fix

Use a test client that sends a request in several slow pieces. A second client should still receive responses. Check that the first request hits its overall deadline even when no individual pause exceeds the idle timeout.

Serve from the repository root with ./sr default.conf.
